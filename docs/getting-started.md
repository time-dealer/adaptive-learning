# 使用教程

## 1. 安装并开始

运行首页安装命令，打开新会话，明确说“使用 adaptive-learning”。如果找不到，运行 `npx skills ls -g` 检查是否存在，并检查宿主是否支持 Skills。只有聊天而没有文件访问能力的环境，无法自动维护本地档案。

## 2. 选一个起点

有目标时这样说：

> 使用 adaptive-learning。我会一点 Excel，想学 SQL，能自己查询订单数据，每周两小时。

Agent 会利用已有信息，最多先问三个关键问题，再用小任务判断基础。你可以说不知道，也可以纠正路线。

只有好奇时这样说：

> 使用 adaptive-learning。什么是循环？先用一个例子讲清楚。

这会直接进入问答探索，不先填问卷。想深入就继续问；想系统学，再表达具体目标。

## 3. 学习时随时调整

| 你的需求 | 可以说 |
| --- | --- |
| 太长 | 再短一点，只讲核心和一个例子 |
| 太抽象 | 换一个生活例子，说明类比的局限 |
| 看过程 | 用流程图或可分步演示解释 |
| 想练习 | 出一道新题，先不要给答案 |
| 卡住了 | 给一个方向提示，不要直接做完 |
| 想跳过 | 这题先跳过，继续后面的内容 |
| 不同意反馈 | 请重新核对依据和我的原意 |

跳过不会被记为掌握，看到答案后的完成也不会被记为独立完成。你决定学习节奏，Agent 不主动催学。

## 4. 档案和新会话

首次持续学习时，Agent 会告诉你实际保存路径。可以指定另一固定目录，默认入口会保存指向它的配置。目录不可写时先解决位置问题，不声称已经保存。

新对话输入“使用 adaptive-learning，继续上次 SQL 学习”。Agent 应读索引和该领域摘要，恢复最后位置；待答问题由你选择回答或跳过。

找不到时提供原目录。不同设备需要能访问同步后的档案，Skill 本身不提供云同步。学习库与安装目录分开，升级 Skill 不应覆盖学习数据。

## 5. 更新和卸载

更新前保留自行修改的 Skill 文件。可重新运行首页安装命令，按安装器提示处理已有安装；学习库无需搬动。

卸载可运行：

```bash
npx skills remove adaptive-learning -g
```

按提示选择宿主。只从 Codex 卸载可以使用 `npx skills remove adaptive-learning -g -a codex`。如果原本安装在项目内，进入原项目目录，去掉 `-g` 后执行。完成后运行 `npx skills ls -g` 检查全局入口；项目安装则运行 `npx skills ls`。

**学习档案不会随 Skill 卸载而删除。** 前提是按本项目约定，将学习库放在 Skill 安装目录之外。

若安装器报告成功，但新会话仍能发现 Skill，请检查公共 `.agents/skills/adaptive-learning` 入口。本次项目范围测试出现了公共目录残留。确认该目录确为本 Skill 安装内容后，可请 Agent 仅移除这个入口并再次检查；若它是符号链接，只移除链接，不删除链接指向的源码。不要删除 `.agents/skills` 整个父目录，也不要动学习库。

| 内容 | 卸载后 |
| --- | --- |
| 所选宿主中的 Skill 安装入口与规则资源 | 由安装器移除 |
| 学习库中的索引、进度、误区和会话摘要 | 保留 |
| 单独保存的练习作品与来源记录 | 保留 |
| 指向自定义学习库的本地路径配置 | 保留 |
| 你手动克隆的源码仓库 | 保留，不属于安装入口 |

重新安装后，告诉 Agent 继续学习；若没有自动找到，提供原学习库路径。不要把学习库放进 Skill 安装目录，以免安装、更新或卸载时影响档案。

如果希望连学习数据也清除，先确认默认入口或 `location.json` 中的真实学习库位置，再自行备份或删除该学习库和对应入口配置。这是独立操作，卸载命令不会代办。不要删除整个 `Documents`、`Codex` 或其他包含无关文件的父目录。

## 常见情况

**搜索不可用：**Agent 应说明限制，继续问诊或用你提供的可信资料，不编造检索结果。

**没有动画：**动画依赖宿主能力；流程图和步骤示意是可用替代。

**评价过于主观：**补充受众、用途、风格与示例，请 Agent 对具体段落说明依据和取舍。

**问题没有得到解答：**直接提醒“现在是问答探索，请先回答这个问题，不要转成课程”。欢迎将脱敏后的失败片段提交到 Issues。
